🚀 What This Software Is

Dirichlet-Splatting is a Windows application that takes measurements collected by a sensor — a radar scanner, a coherent imaging device, or a similar instrument — and turns them into a three-dimensional picture you can look at, rotate, and study. Instead of pointing a camera at an object, it works backwards from the signals the object bounced back, then rebuilds the shape that must have produced them.

The technique behind it is called Dirichlet Splatting: differentiable rendering for wave-based inverse problems. In everyday terms, the software repeatedly draws a guess of the object, compares that guess against your real measurements, and adjusts the drawing until the two match closely. What you see at the end is a faithful 3D reconstruction of whatever was being measured, even when it was out of direct sight or hidden behind another surface.

This is the official implementation released alongside the SIGGRAPH Asia 2026 paper. It is research-grade software used by imaging scientists, radar engineers, and computer-graphics researchers — but the download and the first run are straightforward, and this page walks you through them one step at a time.

✨ What You Can Do With It

You do not need to write any code to get useful results. After you download the application, you can:

  • Rebuild a 3D scene from sensor data. Load a measurement set and let Dirichlet-Splatting reconstruct the shape, position, and surface detail of the objects it describes.
  • Work with wave-based signals. The renderer is built specifically for coherent imaging and radar-style data, where the signal carries phase and direction information rather than just colour.
  • See results as they improve. The reconstruction appears gradually — you watch the model sharpen as the solver refines its estimate, which makes it easy to judge when enough progress has been made.
  • Try different reconstruction settings. Adjust how much detail the solver pursues, how strongly it smooths its estimate, and how many refinement passes it performs, then compare the outcomes side by side.
  • Export your reconstructions. Save the finished 3D result so it can be inspected in other viewers, printed in a report, or shared with colleagues.
  • Run repeatable experiments. Because every stage of the rendering pipeline is differentiable, results can be reproduced exactly when the same settings and the same input are used again.

🖥️ Before You Start

Dirichlet-Splatting is a Windows desktop application. To give it a comfortable place to run and enough room to work, make sure your computer is set up roughly like this:

  • Operating system: Windows 10 or Windows 11, 64-bit edition.
  • Processor: A modern multi-core processor. Intel Core i7 or AMD Ryzen 7 class, or better.
  • Graphics card: A dedicated NVIDIA graphics card with at least 6 GB of memory is strongly recommended. The reconstruction work is heavy, and a dedicated card makes it dramatically faster.
  • Memory: 16 GB of system memory or more.
  • Storage: About 15 GB of free disk space, plus room for your own measurement data and exported results.
  • Display: A screen resolution of 1920 × 1080 or higher, so the 3D views and control panels fit comfortably.
  • Accessories: A mouse with a scroll wheel makes rotating and zooming in the 3D view much easier.
  • Other: A stable internet connection for the initial download, and an up-to-date graphics driver from your card manufacturer.

A quick word of encouragement: if your machine is a little older than the list above, the application will still open and run — it will simply take longer to finish a reconstruction. Start with a small sample dataset before attempting a large one.

🧭 Your First Run, Step by Step

Follow these steps in order the first time you open the application. Each one is short, and you can always close the window and start again if something looks unfamiliar.

  1. 1Open the application. Double-click the Dirichlet-Splatting shortcut on your desktop, or find it in the Start menu and click it. A main window will appear after a few seconds.
  2. 2Wait for the initial setup to finish. The very first launch prepares a few internal components and can take a minute or two longer than later launches. Let it complete without closing the window.
  3. 3Load a sample scene. Choose Open or Load Data and browse to the sample folder included with the application. Pick any of the example measurement sets to begin.
  4. 4Review the settings. Default values are already tuned for the sample scenes. You can leave them as they are for a first run; the panel simply shows how much detail and smoothing the reconstruction will use.
  5. 5Start the reconstruction. Press the Run or Reconstruct button. Progress is shown while the solver works, and the 3D view updates as the estimate improves.
  6. 6Explore the result. Click and drag to rotate the scene, use the scroll wheel to zoom, and hold the right mouse button to pan. Compare what you see against the reference image shown in the sample folder.
  7. 7Save your work. Use Export to write the finished reconstruction to disk. Give the file a clear name so you can find it later.

Once you have completed one full cycle, try the same scene with a slightly higher detail setting. The difference between the two results is the clearest way to build an intuition for how the solver behaves.

🛠️ If Something Goes Wrong

Most first-run problems have simple causes. Check these common situations before anything else.

The download will not start

Reopen the releases page and confirm you are on the newest release entry. Very old browser versions sometimes block large downloads — trying a different browser usually resolves it.

The application opens but the window stays blank

This is almost always an out-of-date graphics driver. Visit the website of your graphics card manufacturer, download the latest driver for your exact model, install it, and restart the computer. Then launch the application again.

A reconstruction runs very slowly

Large datasets are demanding. Try one of the smaller sample scenes first to confirm everything is working, and close other heavy programs while a reconstruction is in progress. If your computer does not have a dedicated graphics card, expect longer run times.

The application closes without a message

This usually points to insufficient memory. Close other applications, restart the computer, and try a smaller dataset. If it keeps happening, note what you were doing immediately beforehand — that detail makes it much easier to track down.

Your measurement files will not load

Check that the file was not still being copied when you tried to open it, and that its format matches the examples supplied with the application. Files exported from other tools sometimes need to be converted first.

Still stuck? The project discussions area is the best place to ask. Include your Windows version, your graphics card model, the exact text of any message you saw, and the name of the dataset you were loading. With those four details, someone can usually identify the cause quickly.

🔍 A Look Under the Hood

You do not need any of this to use the application, but knowing what is happening makes the results easier to interpret.

Dirichlet-Splatting represents a scene as a collection of small local elements — the "splats" in the name — each contributing a piece of the wave field. A differentiable renderer then computes what a sensor would measure if that collection of elements were real, and compares that prediction against your actual measurements. The difference between the two drives an optimisation step that nudges every element slightly, and the loop repeats. Because the whole pipeline is differentiable, the correction signal flows backwards through the renderer cleanly and the reconstruction converges far faster than a naive search would.

The Dirichlet formulation governs how neighbouring elements blend at their boundaries, which is what keeps the reconstruction smooth and physically sensible instead of noisy. The heavy numerical work runs on the graphics card through CUDA, while the surrounding framework is built in PyTorch. The rendering core is written with the Slang shading language, and the project targets coherent imaging and radar-style inverse problems in particular.
